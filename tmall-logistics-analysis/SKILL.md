# 天猫物流到货时长分析

## 必备输入

1. 体验分页面导出的“物流到货时长订单明细”`.xlsx`。
2. 千牛“宝贝销售明细报表”`.xlsx`，需含子订单编号、主订单编号、商品属性、付款时间、发货时间。
3. 页面考核日期、平均到货时长、得分档位、指标权重，以及卖家当前揽收班次。

若需操作商家后台，使用浏览器技能并保持卖家登录态。逐个下载文件并增加间隔，避免浏览器拦截连续下载。所有文件放入当前工作区。

## 执行流程

### 1. 先核验规则与口径

阅读 [references/rules.md](references/rules.md)。不要把“最近30天销售订单”直接当作物流到货时长分母，也不要把明细当成低分典型订单。

必须独立计算导出明细的订单数和平均值，与页面展示值核对。均值四舍五入后不一致时停止，检查考核日期和导出范围，不得继续套算。

### 2. 生成分析报告

运行 `scripts/run_analysis.py`，示例：

```bash
python scripts/run_analysis.py \
  --arrivals "物流到货时长订单明细.xlsx" \
  --items "宝贝销售明细.xlsx" \
  --output "物流到货时长分析.xlsx" \
  --expected-mean 58.76 \
  --pickups "10:00,17:00" \
  --origin "深圳市" \
  --courier "韵达快递"
```

按当月页面调整 `--expected-mean`、班次和四个分数参数。候选时间通过 `--extra-pickups` 设置，必须包含 `18:00` 以支持统一汇总和敏感性分析。

脚本自动完成：

- 子订单号直接匹配；多商品订单按“主订单号＋SKU”唯一匹配。
- 城市、线路、超标准小时和专线情景分析。
- 晚间揽收时点、受益订单和兑现比例敏感性分析。
- 公式化摘要、明细、规则来源和浏览样式。

### 3. 按需加入临时剔除情景

同时提供两个参数：

```bash
--exclude-city "深圳市" --exclude-product-id "1084517287853"
```

剔除条件按“收货城市＋商品ID”同时匹配。将均值复算保留在“临时剔除测算”，将剔除后的全部候选揽收时点、受益订单、节省小时和分数复算保留在“临时剔除揽收测算”。两者均不并入正式改善方案，不表述为平台允许剔除。

### 4. 校验并交付

加载Excel技能，依次运行其 `xlsx_tools.py recalc` 和 `verify`。

- 若使用LibreOffice重算成功，确认原文件内容和样式未受损。
- 若使用formulas副本，只交付原文件；检查重算副本关键结果和全部公式错误。
- 独立从原始数据复算最终回复中的订单数、均值、节省小时、档位和剔除结果。
- 出现任何公式错误、匹配缺失或口径不一致时不得交付。

### 5. 输出优化指引

阅读 [references/report-guide.md](references/report-guide.md)。结论至少包括：考核口径、当前均值、主要城市或线路贡献、推荐班次及受益订单、模拟能否跨档、模型限制和下一步验证动作。

不得把“同步提前”情景写成实际提分保证，不得仅按城市平均值决定专线，也不得把临时剔除混入正式推荐。

## 变更处理

页面档位、权重或指标定义变化时，先更新脚本中的对应规则和测试，再生成报告。实际揽收扫描不可得时，只能把后台发货时间作为可交接时间代理并明确披露。
