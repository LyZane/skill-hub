# 售后退款获取（千牛退款管理导出）

一键脚本：`scripts/export_refund_report.sh [起始日期 结束日期] [--no-import]`
（缺省近 90 天、结束=**今天**；同族流程详见 `docs/09-订单明细自动导出SOP.md`）

## 用途与语义

- 回填订单的**退款原因**（按订单号+金额幂等匹配），供售后洞察按商家编码汇总。
- 退款单按**退款单完结时间**归期计入发生月（当期冲销口径，已结期间不回溯改账）。
- 月度核对前 / 需要分析退款时导出即可，不必每日拉；**补数据清单里别漏掉它**（用户
  2026-10-31 特别强调过）。

## 页面操作要点（入口 `https://qn.taobao.com/home.htm/trade-platform/refund-list`）

1. 「售后单查询类型/快捷查询」选**全部**。
2. 「售后状态」是**多项勾选筛选器，必须全选**（或清空使其不过滤）——实测只勾 1/14 项会
   漏掉大量退款单。设置后点「查询」，确认列表条数明显多于几十条（各状态都在）。
3. 时间类型用**申请时间**，设 起始~结束（日历操作套路同订单：点日期框弹日历、点头部年月
   可展开年月选择器）。
4. 「导出/批量导出」（保持默认全字段）→ 生成报表 → 「请您注意」点确认 → 记录页等
   「处理完成」→ 下载最新任务。
5. 护栏同族：标签页停在导出记录页时必须先回列表页重新操作，**严禁直接下载旧任务**。

## 导入与成功判据

- 端点是**单数** `POST /settings/import/refund`（曾误写成 refunds 导致 404 静默失败，
  见 pitfalls.md #3）。
- **必见「退款报表导入完成：N 条」回执**（或 `sync_runs` 出现 `import_refunds` 记录）才算
  成功，不能只看脚本退出码。手动补导：
  `curl -F "file=@~/Downloads/报表.xlsx" http://127.0.0.1:8000/settings/import/refund`
