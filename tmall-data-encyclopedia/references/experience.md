# 店铺真实体验分获取（千牛「服务报告」页）

一键脚本：`scripts/fetch_experience_score.sh [--no-import]`（回执必见「体验分导入完成：N 天…」）
权威 SOP：`docs/09-订单明细自动导出SOP.md` 第七节

## 源特性（与其他导出截然不同）

- 页面：`https://qn.taobao.com/home.htm/voc-tmall/serverReport`，分数口径＝买家侧同源
  （宝贝质量 35% + 物流速度 20% + 服务保障 45%）。
- **无逐日报表文件**：唯一「导出」按钮产出的是当期 8 项底层考核指标明细
  （`天猫指标表现_YYYYMMDD.xlsx`），**不含逐日历史序列**（2026-11-02 实测确认）。
  所以本源走「AutoGLM 读页面文本 → 解析 JSON → POST 导入」，**不点任何导出/下载按钮**。
- **当天分数 T+1 才出**：页面「更新时间」始终是昨天。水位口径＝页面统计日，别指望拉到今天；
  当天跑完水位还是昨天属正常。
- **历史在「每月趋势」弹窗**：点「趋势」弹出，按自然月展示 4 条线逐日折线。AutoGLM 悬停
  逐点采样（约 9 秒/点）日常顺带采几天；整月回补派专项任务（「10-01 到 10-31 逐日悬停」，
  约 5 分钟）。分数呈块状变动（数日同值后跳变），采样点足以画趋势，整月回补消除断点。

## 脚本流程与解析口径

1. 防呆：8000 端口必须是 uvicorn；复用 qn.taobao.com 标签页；与其他浏览器脚本**串行**。
2. 任务要求 agent 在汇报末尾按固定格式输出（`日期=YYYY-MM-DD 分数=X 商品=X 物流=X 服务=X`
   + `历史: YYYY-MM-DD=X,…`，历史日期必须带年份；解析器兼容 MM-DD 并按主行推断年份、
   跨年自动退一年）。
3. 从 stdout 提取 session id 定位 `task_result.md` → 解析成 JSON → `POST /settings/import/experience`
   → 回显导入回执 → `get_watermark("experience")` 复核。幂等：按 stat_date 唯一，同日重导覆盖。

## 直连研究结论（2026-11-02，待机遇落地）

「每月趋势」数据是页面 XHR 拉的，拿到请求（含 Cookie）即可直连整月秒回。**待用户一次性
协助抓包**：页面 F12 → Network → 打开趋势弹窗 → 找到返回分数的请求 → Copy as cURL。
拿到后：新增连接器直连拉数（或用 `scripts/chrome_exec.sh` 在页面上下文 fetch），浏览器
读取降级为兜底。下次补数时记得问用户一次。

## 故障排查速查

| 现象 | 处置 |
|------|------|
| 「未能从任务结果解析出日期+分数」 | `cat ~/.openclaw-autoclaw/sessions/<sid>/task_result.md` 看 agent 实际汇报格式；页面改版或月初未出分都可能；设置页手动粘贴「日期 分数」兜底 |
| 分数与页面肉眼不符 | 解析器只认 0~100；确认读的是「真实体验分」主线而非子维度线 |
| 当天跑完水位还是昨天 | 正常（T-1），明天再跑即推到今天 |
