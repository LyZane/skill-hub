### 11 · 2026-11-02 · 体验分页读通道的 AppleScript 坑（chrome_exec.sh 已踩平）
- **现象**：osascript 操作 Chrome 标签页报 -1728（找不到对象）；读 JS 文件报 -1700（类型错误）。
- **根因**：Chrome 的 tab 对象没有 index 属性；`read as «class UTF8` 在新 macOS 返回 data 非
  text。另 `execute javascript` 只回同步结果，异步 fetch 拿不到。
- **防呆**：定位用循环内保留的 tab 引用；JS 文件用 shell `cat` 读；异步用两段式
  （先挂 `window.__x`，sleep 后再读）。均已固化在 `scripts/chrome_exec.sh`。

### 9 · 2026-11-01 · 端口 8000 被别的进程占用 → 导入静默 501，对账误报「缺单」
- **现象**：导出下载一切正常，对账却报「21 笔付款扣费单号不在订单表」，触发无谓的浏览器
  重试；看似缺数据，实为数据压根没进库。
- **根因**：当天手动起的 `python3 -m http.server 8000` 占了端口。脚本的「服务在跑」检查
  `curl http://…/settings` 只验证端口有应答（curl 对 404/501 退出码也是 0），导入 POST 被
  SimpleHTTP 拦截返回 501，拿不到 redirect_url、解码打印空行、脚本退出码仍 0。
- **防呆**：① 补数前必验 `curl -sI http://127.0.0.1:8000 | grep -i '^server'` 为 `uvicorn`；
  ② 对账报缺失先查 `sync_runs` 有无本次导入记录、水位是否推进，确认落库再怀疑缺单；
  ③ 已下载文件不必重导出，重启服务后 curl -F 补导。体验分脚本已内置此检查；订单/推广
  脚本的 import 段应升级为「POST 响应 303 且 Location 带 msg= 才算成功」（待办）。

### 8 · 2026-11-01 · 支付宝盘中拉今天，水位却「不动」
- **现象**：同步明明拉到了今天的流水，水位游标停在昨天，像没拉到。
- **根因**：设计如此——今天盘中是部分数据，游标若推到今天会漏晚间流水；次日例行同步整日
  重拉今天补全。
- **防呆**：口径已写入 references/alipay.md；汇报时解释「今天的数已进来，明天例行同步会补全」。

### 7 · 2026-10-31 · 退款导入端点 404 静默失败（refunds → refund）
- **现象**：退款脚本「✓ 已下载」之后再无导入回执，数据没进库，脚本退出码仍是 0。
- **根因**：端点误写成 `/settings/import/refunds`，实际路由是单数 `/import/refund`；curl 拿
  404 无 redirect_url，解码打印空行，不报错。
- **防呆**：任何导入**必看到「导入完成：N 条」回执**（或 `sync_runs` 有对应记录）才算成功；
  手动补导 `curl -F "file=@~/Downloads/报表.xlsx" http://127.0.0.1:8000/settings/import/refund`。

### 6 · 2026-10-31 · 万相台三连坑（凌晨空报表 / 旧任务 / 日历卡）
- **现象**：① 凌晨 01:27 生成的报表 zip 内 CSV 仅表头；② 复用标签页停在「下载任务管理」页，
  任务 2 个动作就把上一轮空报表又下一遍；③ 单日自定义区间点选日期后日历关闭、字段仍显示
  「昨日」。
- **根因**：① 平台「昨日」数据次日上午才生成；② 浏览器 agent 图省事直接下列表里现成的；
  ③ 页面控件缺陷。
- **防呆**：① 凌晨补不到昨日推广属正常，上午再跑，脚本护栏会报「平台数据未生成」且拒绝
  下载空报表；② 任务提示词加「必须先导航回报表页生成新报表，严禁下载旧任务」；③ 日常
  走「过去 N 天」预设，自定义区间只用于补历史。

### 5 · 2026-10-30 · autoglm 长任务 stdout 打印提示行，污染报表路径捕获
- **现象**：`FILE=$(run_export)` 捕获到的不是文件路径而是 `cat .../task_result.md` 提示行，
  校验链路中断。
- **根因**：autoglm ≥1.1.8 对 ≥20 步的长任务会往 stdout 打提示行。

### 4 · 2026-10-30 · 订单导出「漏掉最后一天」的真正机制（半开区间定案）
- **现象**：10-29 首轮导出窗口 10-22~10-28，报表数据只到 10-27，静默漏掉结束日全天约 27 单。
- **根因**：日历把结束日期选对后，控件时分秒停在 **00:00:00**（如 `10-28 00:00:00`），等于
  把结束日当天全天排除在窗口外。
- **防呆**：结束日期选「窗口结束日的**下一天**」、时分秒保持界面默认 00:00:00（半开区间），
  界面零额外操作且不截断当天最后一秒；仅当日历禁选未来日期（当日拉取）才退回 23:59:59。
  脚本另有覆盖校验（文件最新订单日期 ≥ 结束日）+ 对账 + 自动重试一次兜底。

### 3 · 2026-10-29 · 付款扣费对账的 memo 单号口径
- **现象**：对账把合并单误报成漏单。
- **根因**：支付宝扣费 memo 里的单号，合并单是主订单号、单一子单订单是子订单号；只对子单号
  会漏配合并单。
- **防呆**：对账同时匹配 `orders.tid` ∪ `order_items.oid`（`app/services/recon.py` 已如此）；
  且该服务费并非每单都扣（约 355/454），对账是**下界探测**——报出的一定真缺，没报不能证明无缺。

### 2 · 2026-10-27 · 历史订单导出弹窗日期「--」点不动
- **现象**：3 个月前路径导出弹窗里创建时间显示「--」，点击/键入均无响应，试 20 余种交互
  都进不去。
- **根因**：页面筛选未生效——弹窗只带入**已生效**的筛选，不是控件坏了。
- **防呆**：设完筛选必须点「搜索订单」并确认页面时间已变化，再点导出。
