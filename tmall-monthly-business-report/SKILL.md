# 月度经营报告

将平台导出的当月订单明细、做单单号、推广费明细与价格清单，加工为一份多 sheet 的经营报告 Excel，所有计算字段必须是 Excel 公式（打开文件即可追溯计算逻辑），而非写死的数值。

使用当前环境可用的表格读取、编辑、公式写入与渲染能力；已有表格处理规范时遵守其工具与格式要求。不要假设操作系统、客户端、文件位置或月份。

## 开始时引导用户

每次任务需要以下输入，缺失信息尽早集中询问，避免逐条盘问；已提供或已确认的信息不重复问：

| 输入 | 说明 |
|---|---|
| 销售明细 | 平台导出的订单明细 xlsx，含子订单编号、主订单编号、商家编码、购买数量、买家实付金额、退款状态等列 |
| 做单单号 | 补单订单号 txt，每行一个；未提供时须询问，不能默认无补单 |
| 推广费 | 推广平台导出的每日明细 csv（通常 GBK 编码） |
| 价格清单 | 含「商家编码」「预估成本」列的 xlsx |
| 平台费用清单 | 当月各费用项目与金额，**每月必须由用户提供**，含负数退款项 |

## 订单拆分（4 个明细 sheet）

1. **订单-全量**：原始数据，不做任何修改。
2. **订单-补单**：订单号（同时匹配「子订单编号」和「主订单编号」，任一命中）出现在做单单号中的记录。
3. **订单-退款**：在剩余记录中，「退款状态」≠「没有申请退款」的记录（含退款关闭、退货待确认收货等一切非无退款状态）。
4. **订单-有效**：其余记录。**销售统计只基于本 sheet**。

校验：全量 = 补单 + 退款 + 有效，按行数核对互斥与覆盖。txt 中的做单号可能多于明细中匹配到的记录（跨月/未导出）：**补单费按实际匹配到的记录数计**，未匹配单号不计费，但要在财报备注中说明数量。

## 数据检查与标准化

导出的「商家编码」可能与价格清单不一致。**任何无法对应的编码都必须先询问用户，不得自行猜测或丢弃**；其他未提及的数据质量问题（空编码、数量异常等）同样先确认。订单号全程按精确文本处理，不转浮点数。

### 已确认的店铺口径（用户已确认，遇相同情况直接沿用）

编码映射：

| 订单中的编码 | 价格清单编码 | 预估成本 |
|---|---|---|
| 04A | 亚都04A机械款 | 65 |
| 亚都130DWIFI款-金色 | 130DWiFi智能款金色 | 193.5 |
| 亚都130D智能款-金色 | 130D智能款金色 | 179 |

无编码行的处理：

| 行内容 | 处理 |

遇到上表之外的新情况，仍需询问用户。

## 销售统计 sheet

按映射后的商家编码分组汇总，只统计订单-有效：

| 字段 | 口径 / 公式 |
|---|---|
| 商家编码 | 映射后的编码 |
| 售出数量 | Σ 购买数量 |
| 营业额 | Σ 买家实付金额 |
| 销售均价 | `=营业额/售出数量` |
| 预估成本 | 价格清单中的单位预估成本 |
| 平均利润 | `=总利润/售出数量` |
| 毛利率 | `=总利润/营业额` |
| 总利润 | `=营业额−预估成本×售出数量` |

明细行按营业额降序，全部用公式；表头下第一行为「合计」行：数量/营业额/总利润用 `SUM` 求和，均价/平均利润/毛利率由合计值再算。

## 平台费用 sheet

费用项目与金额来自用户当月提供的清单。按金额降序排列（负数项按数值参与排序与求和）；表头下第一行为合计行 `=SUM(B3:B{n})`。

## 推广费 sheet

读入 csv（GBK 编码），每日明细原样保留。表头下第一行为合计行：

- **可求和列**（展现量、点击量、花费、各类成交金额/笔数、购物车数、收藏/加购数、咨询量等计数与金额列）：`=SUM(列3:列{n})`。
- **比率/均值列**用合计值推导，均包 `IFERROR(...,"")` 防除零：
  - 点击率 `=点击量/展现量`；平均点击花费 `=花费/点击量`；千次展现花费 `=花费/展现量*1000`
  - 点击转化率 `=总成交笔数/点击量`；投入产出比 `=总成交金额/花费`；含预售投产比 `=(总成交金额+总预售成交金额)/花费`
  - 总成交成本 `=花费/总成交笔数`；加购成本 `=花费/总购物车数`；加购率 `=总购物车数/点击量`
  - 各类收藏成本 `=花费/对应收藏数`；宝贝收藏率 `=收藏宝贝数/点击量`
  - 引导访问率 `=引导访问量/点击量`；引导访问潜客占比 `=潜客数/访问人数`；入会率 `=入会量/访问人数`
  - 成交新客占比 `=成交新客数/成交人数`；人均成交笔数 `=总成交笔数/成交人数`；人均成交金额 `=总成交金额/成交人数`
  - 「平均访问页面数」无法从汇总推导，留空。
- 比率列用百分比格式 `0.00%`，成本/均值列用两位小数。

## 补单费

13 元/单，按订单-补单 sheet 实际记录数计：`=COUNTA(A4:A{n})*13`，放在订单-补单 sheet 第 1 行（表头之上），旁注口径。

## 财报 sheet（财务模型）

```
当月净利润 = 商品毛利 − 平台费用合计 − 推广费合计 − 补单费
```

各行公式（层层引用其他 sheet）：

| 项目 | 公式 |
|---|---|
| 有效订单营业额 | `='销售统计'!C2` |
| 有效订单售出数量 | `='销售统计'!B2` |
| 预估成本合计 | `=SUMPRODUCT('销售统计'!B3:B{n},'销售统计'!E3:E{n})` |
| 商品毛利 | `=营业额−成本合计` |
| 商品毛利率 | `=毛利/营业额` |
| 平台费用合计 | `='平台费用'!B2` |
| 推广费合计 | `='推广费'!F2` |
| 补单费用 | `='订单-补单'!B1` |
| 费用合计 | 三项相加 |
| 当月净利润 | `=毛利−费用合计` |
| 净利率 | `=净利润/营业额` |

备注区必须写明：统计口径（剔除补单/退款各多少单）、未匹配做单号数量、剔除/映射的特殊行。

## 输出格式与样式

- 输出到当月目录，文件名 `驰梦 X 月经营报告.xlsx`（店铺与月份按实际替换）。
- **Sheet 顺序（左→右，概览在前、明细在后）**：财报 → 销售统计 → 平台费用 → 推广费 → 订单-有效 → 订单-退款 → 订单-补单 → 订单-全量。
- **统计性内容放在表格数据上方**：各 sheet 合计行在表头正下方；订单-补单的补单费在第 1 行。
- 样式约定：
  - 表头：深蓝底（#305496）白字加粗、居中、行高 24、冻结窗格
  - 合计/统计行：浅黄底（#FFF2CC）加粗
  - 财报：章节标题浅蓝底（#D9E1F2）；净利润行浅黄底 + 红色加粗字体
  - 明细行细边框（#BFBFBF）；列宽按内容自适应（上限 45）
  - 比率列 `0.00%`，金额列 `#,##0.00`

## 校验与交付

保存前完成：订单行数拆分守恒；每个 sheet 行数与预期一致；合计公式范围覆盖全部明细行；保存后重新打开验证公式与样式。交付时列出：输出文件、各 sheet 行数、营业额/毛利/三项费用/净利润，以及集中列出的未决问题（未匹配做单号、新出现待确认编码等）。
